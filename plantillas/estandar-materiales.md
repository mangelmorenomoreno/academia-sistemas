# Estándar de materiales por clase

Toda clase desarrollada incluirá carpetas presentaciones (PPTX editable, PDF y cuando proceda HTML), lecturas (PDF y fuente), ejercicios (ejemplos resueltos y problemas de análisis), practicas (materiales, seguridad, procedimiento, resultados, rúbrica), pruebas (evaluación separada), soluciones (respuestas razonadas y rúbrica), recursos (diagramas, enlaces verificados a videos y simuladores). Mantener README con orden de estudio, duración, prerrequisitos y estado. Verificar documentos y enlaces antes de marcar la clase como revisada. No publicar datos personales. Las clases planificadas no se considerarán desarrolladas hasta que tengan estos materiales.

## Estándar editorial

Cada README debe incluir portada, navegación y secciones claras. Los capítulos desarrollados tendrán ilustraciones explicativas con leyenda, tablas, ejemplos resueltos, recuadros de errores comunes y enlaces comprobados. Las lecturas largas tendrán un índice. Los videos incluirán una tarea de observación o análisis. Diferenciar el material planificado del material desarrollado. Validar el renderizado de documentos antes de declararlos revisados.

## Estándar de navegación e ilustración

- Cada concepto debe tener una explicación causal: qué es, por qué ocurre, qué lo provoca, qué cambia y qué permanece.
- Una página por concepto, con navegación anterior/índice/siguiente arriba y abajo. El cierre enlaza con la próxima clase, señalando explícitamente si está pendiente.
- Cada lectura debe incluir una imagen específica del fenómeno, no solo portadas. Los procesos temporales tendrán fotogramas consecutivos y, cuando sea útil, GIF.
- PDFs: diagramas en cada página de contenido; los PDF presentan secuencias estáticas porque no reproducen GIF de manera fiable.
- Presentaciones: una visualización por paso, legible y científicamente coherente.
- Plantillas: fuente editable y PDF imprimible, con enlaces directos en una biblioteca de descargas.
- HTML: índice, flechas del teclado, indicador de página y controles anterior/siguiente. No afirmar que existe un sitio desplegado si no se ha habilitado GitHub Pages.
- Comprobar conteos, signos, direcciones de flechas, enlaces y archivos antes de publicar. No representar órbitas esquemáticas como trayectorias reales.
